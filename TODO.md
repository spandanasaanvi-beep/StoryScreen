# StoryScreen implementation outcomes

## Existing working features to preserve

- [x] **Interactive StoryScreen MVP.** Keep the existing guest-accessible React, TypeScript, and Vite StoryScreen with its premium dark streaming-style design; Home, Story Library, Create Adventure, Story Player, Ending, Story History, and Settings screens; the three named adventures; deterministic branching choices and multiple endings; continuity; local save/resume/replay; optional family voting, character customization, narration, captions, and accessibility settings; and keyboard/remote-oriented controls.

## Story-to-video request

- [ ] **Landing page and genre selection.** Step 1: Display a premium, cinematic landing page with the StoryScreen logo, the tagline “Every choice changes the story,” and a prominent **Create Your Story** button. Step 2: After clicking the button, display selectable genre cards for **Fantasy; Mystery; Science Fiction; Comedy; Adventure; Folktales & Mythology; Bedtime Stories; Inspirational Stories**. The selected genre determines the next form.

- [ ] **Dynamic, accessible story form.** Step 3: Display a dynamic form based on the selected genre. Ask only relevant questions. Include genre-specific fields: Fantasy—magical world, hero, magical powers, creatures, quest; Mystery—mystery type, detective, setting, clues, desired reveal; Science Fiction—planet, futuristic technology, protagonist, mission; Comedy—characters, situation, humor style, setting; Adventure—protagonist, destination, obstacles, goal; Folktales & Mythology—tradition or mythology, characters, moral, setting; Bedtime—main character, dream world, mood, lesson; Inspirational—main character, challenge, goal, message. Include common inputs: story title (optional), language, target audience, video duration, visual style, narration voice, and aspect ratio. Include a **Generate My Video** button. Validate empty/invalid inputs and display clear, accessible error messages while preserving the existing design and providing large responsive controls.

- [ ] **Coherent, safe story drafting and visual scene structure.** When the user submits the form, validate the selected inputs; create a coherent story from the selected genre and details; divide the story into scenes; and generate or obtain suitable visuals for each scene. Submitted genre and form details must influence the story and its scene selection/visual presentation. Draft through the built-in Manus AI service only on the server, with a request timeout and strict validation; if AI is unavailable, returns an error, or provides invalid output, generate a usable deterministic script from the same inputs. Keep server credentials server-side and do not require a third-party API key for basic/local functionality.

- [ ] **Actual video rendering and honest status.** Add narration and subtitles when available. Combine scene visuals into a playable video with audio when supported. Use FFmpeg and packaged artwork to render a real MP4, not a loading-animation simulation or static image. Display a real progress indicator and useful status messages only while work is occurring. Do not report success unless a playable video file was produced and verified. If narration is unavailable, provide a clear, working captioned-video fallback; show meaningful render/API errors and allow retry.

- [ ] **Dedicated playback, replay, download, and persistence.** Open the finished MP4 in a dedicated video player. Provide Play/Pause, Replay, Download when supported, and Create Another Story controls. Save generated stories and video Blobs in browser storage when supported, handle storage quota/failure honestly, and keep a direct download option for durable user-owned copies. Preserve the existing interactive stories, routes, saves, and accessibility features.

- [ ] **Hybrid runtime, API, and security.** Keep the existing frontend and local fallback available. Add a same-origin Node API for story generation and video rendering, keep `MANUS_API_KEY` server-only, validate and bound inputs/responses/files, clean temporary render files, and provide an unauthenticated health endpoint. Keep `/api/*` routed to the server and page routes to the Vite static output/SPA fallback. Document any required service variables and local FFmpeg/eSpeak setup. Explain accurately that this renderer creates an illustrated-motion MP4 rather than AI-generated moving footage; explain any external service/API requirements. Do not publish the project during this implementation.

- [ ] **Complete journey, responsive design, retries, and existing-project constraints.** Preserve the premium dark streaming-style design. Keep code maintainable and reuse existing components. Provide accessible forms and responsive controls. Handle loading, failures, retries, and empty inputs. Keep free/local functionality available wherever practical. Do not rebuild the project from scratch or remove working features. Test the entire journey: website → genre → dynamic inputs → generation → playable video; also verify that submitted inputs actually influence the generated story and video. Fix existing bugs. At completion, report which parts work, whether real video files are generated, and which features require external APIs or additional setup. Never claim an unverified feature.

**Approval constraints:** automated end-to-end rendering tests use the deterministic/local story path and do not spend a live Manus AI call. Automatic publishing remains off.
